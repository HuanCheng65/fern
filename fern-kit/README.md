# fern-kit

Fern 的设计系统，产品（`fern-ui`）和官网（`fern-site`）共用同一份。

进这里的标准只有一条：**不依赖 Tauri，也不依赖任何一端的运行环境**。

## 样式

`fern-kit/styles` 一次引入，四层，从下往上：

| 层 | 是什么 |
| --- | --- |
| `brand.css` | 品牌四色。整个系统里唯一写死颜色的地方，挂在 `:root`，不给任何东西上色。 |
| `scale.css` | 间距、字号、圆角、时长、控件高度。与明暗无关，纸白和墨松是同一套节奏。 |
| `surface-dark.css` | 颜色。压在这张表面上的字色、发丝线、浮层、以及背景交出来的色板。 |
| `elements.css` | 元件与基础规则。只用语义名，所以换一张表面就换一身皮。 |

挂法是 `class="fern fern-dark"`：`.fern` 说「这一块用 Fern 的设计系统」，
表面类说「用哪张皮」。产品挂在 body 上等于挂在根上；官网只挂在那几块「把真
界面拆出来摆在纸上」的片段上，纸白的正文碰不到。

两条硬规矩：

- **组件里不准出现十六进制。** 颜色一律问语义名要，否则换表面时它不会跟着变。
- **元件的作用域写 `:where(.fern)`。** `:where()` 不贡献特异度，选择器权重和
  它没被搬出来时逐位相同；写成 `.fern .btn` 就会和组件里的局部覆盖打平，
  谁赢取决于打包顺序。

运行时要改这些变量，只能改到挂着这两个类的元素上——`fern-kit/scope` 是那条
唯一的路，原因写在文件里。

## 两层组件

界线是**它认不认识 Fern 的名词**（实例、模组、崩溃、补给）。

`ui/` 只认形状。一颗按钮不知道自己会被用来删什么，一张封面不知道那是谁的实例。
它可以出现在任何一张 Fern 的界面上，也可以出现在官网的任何一块里。

名字用惯例的那个，不自己造词——`SegmentedControl` 是 Mantine / Radix Themes /
Chakra 都在用的名字，`Dialog` 是 ARIA 和所有主流库的叫法。造一个只有本仓库懂的
名字，等于要求每个新来的人先学一遍我们的方言。

| `ui/` | 是什么 |
| --- | --- |
| `Button` | 按钮。variant 说重量，tone 说这个动作是什么性质。 |
| `Field` | 一个带标签的控件。它管的是**关联**：生成 id 并绑 `for`、`aria-describedby` 指向说明、`aria-invalid` 加错误行。 |
| `Input` | 单行输入框。`label` / `hint` / `error` 直接收 prop，内部走 `Field`。 |
| `Select` | 下拉。替掉原生 `<select>`——那一层的菜单由系统画，CSS 够不着，三个平台还各不相同。 |
| `SegmentedControl` | 分段选择器。用得第二多的控件，所有「N 选一」都是它。 |
| `Dialog` | 打断当前场景的那一层：遮罩加一块玻璃面板。整个界面唯一「有实体」的表面。 |
| `Mark` | 标志。7×9 网格上的一条直角螺线，加载动画沿走线点亮。 |
| `Cover` | 群系封面。 |
| `ui/field` | `Field` 递给控件的那几样属性，`Input` / `Select` / `SegmentedControl` 都按它接。 |
| `ui/mark` | 标志的几何。存的是八段走线而不是导出的 SVG——走线的顺序也是规格的一部分。 |
| `ui/biome` | 群系色场。三颗种子（名字、时长、钟点）决定一张脸，实例封面和官网的底子用的是同一支笔。 |

`parts/` 认得 Fern 的名词。它们仍然是 presentational（给数据就画，不自己去取），
只是数据的形状是这个产品特有的——所以官网也能拿它们讲真话。

| `parts/` | 是什么 |
| --- | --- |
| `Advice` | 一条诊断：说清是什么，能修就给一颗按钮。 |
| `CrashPanel` | 游戏崩了之后说的那句话。 |
| `SupplyCard` | 补给站的一张资源卡。 |
| `PaletteRow` `PalettePanel` `CommandPalette` | 直达。 |
| `parts/palette` | 直达的引擎。一张注册表：各特性自己调 `provides()` / `commands()` 注册，匹配、拼音、排序、使用习惯都在这里，不碰任何数据源。 |
| `parts/advice` `parts/crash` `parts/supply` | 上面那几个认的形状。 |

**`parts/` 可以用 `ui/`，反过来不行。** 一旦 `ui/` 里出现了「实例」，这条线就没了。

| 别的 | 是什么 |
| --- | --- |
| `fern-kit/scope` | 运行时改变量时，改到哪个元素上。 |
| `fern-kit/host` | 宿主装进来的东西：动效倍率、离屏画笔。见下。 |

## 那个空壳

组件确实需要两样只有宿主知道的东西——「减弱/关闭动效」的档位（存在设置里，
Svelte 的过渡要数字，读不了 CSS 变量），和画群系图的常驻 Worker（产品那边的
基建，官网没有）。`fern-kit/host` 就是给它们留的空壳：两样都有能用的默认值
（不减速、主线程画），宿主想接就在启动时接上去。

组件只认这个壳，不认谁装的。所以同一个组件既能落在启动器里，也能落在一张
静态页面上——官网什么都不装，照样画得出来。

## 不进这里的

读写 Tauri 的（`instances.svelte.ts` 那类往注册表里塞真实数据的）、主题
（经 `persist.ts` 连着 Tauri）、以及任何需要知道「现在有哪些实例」的东西。

组件这边的界线是**presentational**：给它数据它就画，不自己去取。`CommandPalette`
是个例外——它接着那个全局 store，因为官网要的正是「真的会搜的那一个」。

## 别的

这是一个**源码包**，没有构建步骤：两端都是 Vite，直接编译 `src/` 下的
TypeScript 和 runes，省掉一层产物和一层 sourcemap。

改这里的东西，两边都会跟着变——所以改之前先确认另一端也说得通。
