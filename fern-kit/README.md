# fern-kit

产品（`fern-ui`）和官网（`fern-site`）共用的那部分。

进这里的标准只有一条：**不依赖 Tauri，也不依赖任何一端的运行环境**。

| 模块 | 是什么 |
| --- | --- |
| `fern-kit/mark` | 标志的几何。7×9 网格上的一条直角螺线，存的是八段走线而不是导出的 SVG——走线的顺序也是规格的一部分，加载动画沿它点亮。 |
| `fern-kit/biome` | 群系色场。三颗种子（名字、时长、钟点）决定一张脸，实例封面和官网的底子用的是同一支笔。 |
| `fern-kit/palette` | 直达的引擎。一张注册表：各特性自己调 `provides()` / `commands()` 注册，匹配、拼音、排序、使用习惯都在这里，不碰任何数据源。 |
| `fern-kit/tokens` | 度量与色板。变量挂在 `.fern-app` 而不是 `:root` 上——产品把这个类挂在 body 上等于挂在根上，官网只挂在露出来的那一块上，纸白页面碰不到。 |
| `fern-kit/host` | 宿主装进来的东西：动效倍率、离屏画笔。见下。 |
| `Mark` `Cover` `Overlay` `PaletteRow` `PalettePanel` `CommandPalette` | 组件。 |

## 那个空壳

组件确实需要两样只有宿主知道的东西——「减弱/关闭动效」的档位（存在设置里，
Svelte 的过渡要数字，读不了 CSS 变量），和画群系图的常驻 Worker（产品那边的
基建，官网没有）。`fern-kit/host` 就是给它们留的空壳：两样都有能用的默认值
（不减速、主线程画），宿主想接就在启动时接上去。

组件只认这个壳，不认谁装的。所以同一个组件既能落在启动器里，也能落在一张
静态页面上——官网什么都不装，照样画得出来。

## 不进这里的

读写 Tauri 的（`instances.svelte.ts` 那类往注册表里塞真实数据的）、主题
（经 `persist.ts` 连着 Tauri）、以及任何需要知道「现在有哪些实例」的东西。

组件这边的界线是**presentational**：给它数据它就画，不自己去取。`CommandPalette`
是个例外——它接着那个全局 store，因为官网要的正是「真的会搜的那一个」。

## 别的

这是一个**源码包**，没有构建步骤：两端都是 Vite，直接编译 `src/` 下的
TypeScript 和 runes，省掉一层产物和一层 sourcemap。

改这里的东西，两边都会跟着变——所以改之前先确认另一端也说得通。
