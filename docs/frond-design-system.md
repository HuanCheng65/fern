# Frond 设计系统

Frond 是 Fern 的产品设计系统，用于统一界面结构、视觉表达与交互行为。

其目标是在承载复杂 Minecraft 功能的同时，保持清晰、安静、一致，并允许内容塑造界面的个性。

## 核心原则

### 内容优先

界面服务于内容，而非让内容适配固定模板。

实例、世界、内容资源等可以直接参与视觉呈现，成为界面的一部分。

### 个性来自内容，一致性来自系统

内容可以影响封面、强调色、环境色与局部视觉氛围，但不得破坏信息层级、语义颜色、可读性与交互规则。

视觉可以变化，产品逻辑必须保持稳定。

### 默认安静

无持续任务或异常状态时，界面应尽可能减少干扰。

下载、安装、启动、联机、警告与错误等状态统一管理，仅在需要时呈现。

进行中的状态持续显示；完成状态及时退出；需要处理的问题保留至解决或忽略。

### 突出当前最重要的操作

单一上下文中原则上只保留一个主要操作。

次要操作应在视觉层级上明确降级，避免多个元素同时争夺注意力。

### 复杂信息渐进呈现

默认展示完成当前任务所需的信息。

技术细节、高级设置与低频能力通过进一步操作展开，不直接堆叠在主要界面中。

### 相同的事情使用相同的方式完成

相同类型的操作应遵循一致的入口、反馈、确认与结果呈现方式。

优先复用既有交互模式，不为单个页面重新定义行为。

### 仅在需要边界时创造边界

容器用于表达明确的分组、层级或交互边界。

能够通过留白、排版、对齐和层级表达关系时，不额外增加卡片、面板或装饰性容器。

## 系统结构

### Foundations

定义基础视觉规范：

* Typography
* Spacing
* Radius
* Grid
* Density
* Iconography

所有页面与组件统一使用基础尺度，不直接引入任意值。

### Tokens

以语义 Token 管理视觉属性，包括：

* Surface
* Content
* Accent
* Border
* Status
* Focus
* Disabled

组件依赖语义 Token，不直接绑定具体颜色或主题值。

### Frond Ambient

负责内容与视觉环境之间的映射。

实例封面、内容资源等可生成或选择相应的环境色、强调色和表面色调，同时遵守对比度、语义颜色与可读性约束。

### Components

维护可复用的界面组件及其状态，包括按钮、输入框、菜单、卡片、对话框、标签、进度、状态岛等。

组件负责一致的视觉和基础行为，不承担具体业务流程。

### Patterns

定义跨页面复用的交互模式，包括：

* 创建与管理实例
* 安装与移除内容
* 选择账户
* 管理进行中的任务
* 处理异常
* 删除与确认
* 修改高级设置
* 创建与恢复备份

新增功能应优先复用既有 Pattern，再考虑扩展系统。

## 主题与个性化

主题通过 Design Token 影响视觉表现，不直接覆盖组件实现。

允许调整的内容可以包括强调色、背景、环境效果、圆角、密度等；信息层级、语义颜色、交互行为与可访问性规则不随主题改变。

## 设计评审准则

新增页面、组件或交互应至少确认：

1. 当前最重要的信息和操作是否明确。
2. 是否默认展示了不必要的信息。
3. 是否存在可以移除的容器或装饰。
4. 是否复用了已有组件与交互模式。
5. 内容驱动的视觉变化是否破坏系统一致性。
6. 状态与反馈是否进入统一的状态体系。
7. 个性化是否通过 Token 实现，而非绕过系统。
