# 启动器设计文档

> 状态：设计理念与风格已定稿，功能细节待展开。
> 本文档沉淀了设计侧的核心决策，功能规划另开文档。

## 一、理念

**启动器是画框，玩家的世界才是画。**

界面本身退到几乎没有装饰，视觉表达来自玩家自己的内容和从中提炼的色彩。启动器出厂时素净，用一个月之后每个人的都长得不一样。这样「极简」和「个性化」这对天然打架的目标可以同时成立：秩序由我们守，个性由玩家填。

三条原则从理念推出：

**内容即装饰。** 界面自己不画花纹，装饰性由封面、色彩、玩家内容承担。代价是空状态必须单独设计好，第一次打开、什么都没有的那一屏，要靠排版和留白本身撑住。

**一次只回答一个问题。** 启动器的真实使用场景是打开、点启动、最小化，全程三十秒。首页只回答「现在玩哪个」，启动是英雄交互，其余功能全部退到二级。

**约束下的自由。** 个性化通过结构化参数给出：格子是我们画的、尺寸是我们定的、视觉规范是我们出的，玩家决定放什么和放哪。参考 PCL2 自定义主页的教训——给完全自由的画布，社区会做出网页一样乱的主页。

一条贯穿性的技术哲学：主题、封面、widget 布局都是声明式的。一套配置就是几 KB 的文件，可分享、可回滚、可复现。

## 二、群系：生成式设计语言

每个实例配一张生成式数字艺术封面，风格为扁平几何色块构图。设计语言命名为「群系」：每个实例是一个群系（深海、丛林、下界、末地、恶地……），色板借群系的色彩记忆命名。这是对 Minecraft 视觉基因的引用方式——不碰像素 UI，借世界观当骨架。

生成系统有三层种子：

1. **恒定种子**：实例 ID 或名字的哈希。决定构图骨架和基础色相（用哪套模板、色块怎么摆、落在哪个色系）。永不改变，封面就是实例的脸。
2. **生长种子**：游玩时长、mod 数量等累积量。缓慢影响构图丰富度——新实例的封面疏朗，玩了两百小时的实例层次更密，像年轮。这是养成感的来源。
3. **环境种子**：真实时间，映射到 Minecraft 的昼夜循环。清晨偏冷偏亮，正午最清透，黄昏染暖橙，深夜整体沉下去。只作用于色温和明度，构图不动。

三条纪律防止「活」变成「乱」：

- 骨架稳定，扰动只碰次要视觉层
- 变化以小时和天为单位，永远不在眼皮底下动
- 完全确定性：同样的种子生成同样的画，封面可导出为几行参数

构图模板做成有限集合（大圆相切、色带分层、颗粒散布等），后续作为个性化参数开放选择。

生成式封面的视觉风格本身就是产品识别度：别人截图发群里，一眼认出是这个启动器。

## 三、视觉语言

**风格基调（待定）**，两个候选，需要各出一张同界面对比稿后拍板：

- 冷调科技极简：Linear、Vercel 一路。深色为主、高精度、细线条，和游戏截图（多为暗色场景）搭配好。缺点是近年被用得多，容易撞脸。
- 暖调纸感极简：暖白底、柔和阴影、微弱纸质感，日式文具审美。启动器品类里没人做过，且与 Minecraft 的木头泥土色系亲和。

目前倾向：暖纸感做浅色主题的人格，深色主题往影院感做，两套都认真设计而非互相反色。

**现代感的三个落点：**

- 排版建立层级：大字号标题，数字直接当视觉元素用
- 动效：spring 曲线、启动转场，现代感一半来自会动的部分
- 留白的节奏感：疏密对比，而非均匀 padding

**明确避开的东西：** Material Design 3 和 Fluent 的模板观感（Zalith 2 已是标准 MD3），全像素 UI（容易土）。MC 基因只做克制引用：加载动画用方块堆叠、图标里偶尔的像素细节、场景命名的世界观词汇。

## 四、信息架构：横向舞台

整个启动器是一条横向排列的场景带，五个场景从左到右固定排开：

**启动 · 实例 · 补给 · 联机 · 衣柜**

（命名带世界观风味：资源下载叫补给，皮肤叫衣柜。也可全换直白命名，社群语感待验证。）

切换场景时镜头横向平移，背景色随场景插值过渡。群系系统给了每个界面颜色，这些颜色连成一条连续的世界，导航是在世界里移动。空间位置固定，形成肌肉记忆。这套模型来自游戏机（PS5、Switch、Steam 大屏模式），天然内容优先且手柄友好——未来做电视端或掌机模式，方向键左右移动就是全部交互。文档调研里 Prism 的大屏模式需求挂了四年没人做，这是个储备的差异化点。

**关键判断：** 启动器的复杂度大部分是实例内的复杂度（mod、资源包、光影、存档、Java 设置、日志），全部收进实例详情页内部分区管理，不摊在全局导航里。

**导航形态：** 顶部一行纯文字，五个词、大字距，当前场景实色、其余淡出。不做侧栏、不做图标栏、不用图标——文字导航是杂志和作品集的语言，用来压 SaaS 味。设置和账户缩在右上角，不占场景位。场景数量有弹性，联机上线前那个词可以先不出现。

反 SaaS 的具体手段总结：不做左侧图标栏加列表-详情布局，每个场景有自己的主视觉（补给页铺整合包封面瀑布流，联机页用皮肤渲染做头像卡片，衣柜把皮肤 3D 渲染放舞台中央），列表和表格只出现在真正需要密度的地方（如 mod 管理）。

**转场性能要求：** 横向平移 200ms 以内，带弹性曲线。标杆是 PS5 的场景切换速度。

## 五、首页

首页是「正在播放」页：一个实例、封面铺满环境、实例名、一颗启动键。点实例名呼出切换器，点封面进实例详情。

**Widget 体系（HUD）：**

- 出厂零 widget，每一个都是玩家自己加的，极简对不折腾的人始终成立
- 视觉上按游戏 HUD 设计：吸收当前群系色、半透明浮在封面艺术上，长在世界里而非浮在世界上
- 尺寸分档（1×1、2×1、2×2），吸附隐形网格
- 首批官方 widget 候选：服务器在线状态、好友列表、本周游玩时长、mod 更新提醒、下载进度、快照资讯
- Widget API 后置。PCL2 主页插件生态证明社区创作欲真实存在，用沙盒化的 widget 格子接住它，第一版先做五六个官方的

**命令面板：**

⌘K 呼出，全局唯一。实例切换器与它是同一个东西（点实例名呼出时预过滤到实例）。可搜实例、动作（启动、打开游戏目录、导出整合包、切换账户）、补给站资源、设置项。

- 拼音模糊匹配必须有，中文实例名用首字母能搜到
- 视觉走群系色、深色半透明，不抄 Raycast 原样
- 定位：导航服务九成普通玩家，面板服务一成键盘玩家，两边不迁就对方。HMCL、PCL2 社群折腾党比例高，这功能价值大
- 面板是加速器，GUI 必须保持功能完整，不能拿面板当借口埋功能

## 六、背景层级系统

背景从「一张封面」升级为四层结构，自上而下：

1. **内容层**：文字、按钮、widget
2. **遮罩层**：按需出现的可读性暗角。检测文字区域背后亮度，超标就淡入局部遮罩，平时隐形
3. **特效层**：粒子、视差、转场
4. **背景层**：可插拔源，四种——
   - 生成式群系封面（默认）
   - 静态壁纸（图片）
   - 视频壁纸（循环短片）
   - 桌面透出（窗口半透明，桌面壁纸自己透进来。Wallpaper Engine 没有公开接口可读，透明窗口是覆盖 WE 用户的正确实现，零适配）

**支点规则：任何背景源都必须交出一份色板。**

生成式封面天生自带；图片和视频跑颜色量化（Material You 的 k-means 提主色思路，视频抽几帧）；桌面透出模式截屏采样。提取的颜色吸附到最近的预制群系色板，而非直接使用——这一步是护栏，保证再奇怪的壁纸也不会把 UI 染成脏色，文字对比度始终达标。

色板进入 token 系统后，导航、widget、命令面板、启动键自动跟色。换任何壁纸，设计语言完好，壁纸看起来像启动器原生的一部分。这是与「贴图式换肤」的本质区别：别家换主题是给 UI 蒙皮，我们让 UI 向背景学色彩。

## 七、特效与动效

特效层只做三种，多一分就往 QQ 秀滑一分：

- **视差**：鼠标移动时背景反向漂移几像素，前景 widget 漂得更少，产生纵深
- **景深**：呼出命令面板或切换器时，背景模糊下沉、焦点浮上来
- **粒子**：群系环境特效（下界烬火、雪原落雪、深海气泡）。壁纸模式下粒子用提取色板染色，与背景始终同族。启动转场也由粒子层承担，通用于所有背景源

其他动效：

- 待机呼吸：封面色块以分钟为尺度极缓慢漂移，几乎不可察觉，但界面没有死住
- 换装过渡：房间、人数、昼夜引起的配色与构图变化不跳变——画面交叉淡化约一秒半，色板逐帧插值，整个界面的颜色一起滑过去
- 启动转场：按下启动键，色块散开再聚拢成进度指示，完成后沉下去

## 八、性能红线

调研文档里 Overwolf 被骂到今天的原因就是常驻吃资源。硬性要求：

- 视频壁纸硬解码，帧率上限 30
- 窗口失焦立刻暂停所有动态背景和特效
- 游戏启动后整个渲染层休眠
- 「启动器比游戏还烫」是不允许出现的差评

## 九、个性化出口清单

全部出口：背景源、色板（可锁定群系）、特效开关、widget 摆放、封面构图模板、场景命名风味、字体、密度、圆角、明暗。

以上打包为一个声明文件即「主题包」，几 KB，可分享、可回滚。社区主题工坊是自然延伸，首发时官方自出几套主题包。


## 十、页面内导航：布局宪法

页面内导航最怕的是各自为政——补给用左侧栏、实例详情用顶部 tabs、设置又发明第三种，用户每进一个页面都要重新学一遍。所以先定原则，再从原则推出预设布局，之后所有页面只许从预设里选，不许发明新的。

预设不是文档里的建议，是 `src/layouts/` 下的五个组件。写成文档没人遵守，写成组件才叫约束。

### 三条语法

**一、横向换地方，纵向改视图。**

全局导航已经占用了「横向平移 = 切换场景」这个隐喻，场景内的导航延续同一套语法而非另起炉灶：

- 凡是「我在看另一个东西」的切换，一律横向、放在内容上方——场景切换、详情页的 tabs。
- 凡是「我在换一种看法」的操作，一律纵向、放在内容左侧——筛选器、锚点目录、排序分组。

前者改变内容的身份，后者只改变内容的呈现。视线水平移动是在「去别处」，垂直移动是在「调整眼前这个地方」。

这条语法自动禁止了一类坏设计：左侧栏永远不承担导航职责，所以永远不会出现「左侧栏套 tabs」那种企业软件的层级迷宫。

**二、层级重量递减。**

| 级 | 位置 | 字号 | 状态 |
| --- | --- | --- | --- |
| 一 | 顶栏场景词 | 14px / 500 | 当前实色，其余 40% |
| 二 | 页面内横向 tabs | 13px / 500 | 同上，整体更小 |
| 三 | 左侧纵向控件 | 12px | 当前实色，其余 40%，标题 35% |

三级单调递减，扫一眼就知道哪层是哪层。**任何一级都不许用背景色块或边框强调自己**，全部靠字重和透明度，和顶栏保持同一种安静。

**三、吸附边界。**

吸附元素（详情布局的 tabs、浏览布局的搜索行）吸附在顶栏下缘，**永远不和顶栏融合**——顶栏是场景层的领土，页面元素到此为止。毛玻璃的浮现时机统一由 `nav.scrolled` 控制，写在布局系统层面，不由各页面自己实现。

### 五个预设

| 布局 | 形态 | 用在哪 |
| --- | --- | --- |
| `Stage` | 全出血内容，零页面导航，UI 浮在艺术之上 | 启动场景 |
| `Collection` | 顶部一行轻量控制，下方网格 | 实例场景首页、衣柜首页 |
| `Detail` | 横幅 + 横向 tabs + 单一内容区 | 实例详情、项目详情、房间详情 |
| `Browse` | 顶部搜索框，左侧纵向筛选，右侧结果流 | 补给场景 |
| `Form` | 左侧锚点目录，右侧单列表单流 | 设置 |

五个布局对应五种内容形态：**展示一个、陈列一堆、深入一个、寻找一个、配置一堆。** 如果将来出现了不落在这五类里的页面，先怀疑那个页面本身设计错了。

几条细则：

- `Detail` 的滚动行为定死在布局里：横幅照常滚走，tabs 那一条吸附在顶栏下缘，标题滚出视野后在这一条右侧补一个小标题。长模组列表滚到深处，你仍然看得到自己在哪个实例的哪个 tab。
- **吸附元素的高度恒定。** 让它随滚动改变高度，等于在滚动过程中改变文档高度：内容会跳，短页面还会在「变矮所以不该收缩、于是变高」之间来回抖。滚动中唯一允许变的是不占位的东西——透明度。
- **毛玻璃只属于顶栏和浮层。** 页面内部的列表滚到哪，跟顶栏没有关系；顶栏的玻璃只由页面主滚动容器（`data-page-scroll`）触发。`backdrop-filter` 一律同时写 `-webkit-` 前缀，WebKitGTK 只认带前缀的那个。
- `Detail` 的内容按 tab 性质分两档：列表类（模组、存档、日志）吃满宽度，阅读类（概览、设置）压到 68ch。
- `Browse` 的搜索框是这套布局唯一允许的重型控件——搜索是浏览型页面的核心动作，值得付出视觉重量。左栏定宽 200px。
- `Form` 的锚点和 `Browse` 的筛选栏都在左侧，职责一致：都在回答「眼前这个长东西，我要看哪一段」。语法没有破。
- 空白是排印的一部分。内容不满铺是刻意的克制，不是没排完。

### 一条禁令

**任何布局内，横向 tabs 之下不许再出现横向 tabs。**

某个 tab 的内容多到想再分组——比如设置 tab 想分「Java / 显示 / 网络」——用 `Form` 的纵向锚点方案。二级 tabs 是结构失控的第一个症状，从语法层面掐死它。

## 十一、点击区：视觉大小 ≠ 判定大小

这套界面的第三级控件是刻意的纯文字——12px 的筛选项、没有边框的链接按钮、顶栏那几个词。视觉上这是对的，**错的是把「看起来多大」和「点得到多大」绑成了一件事**：一个 20px 高的盒子等于逼用户拿鼠标去瞄准，而鼠标不像手指有容错。

所以放大的是判定区，不是视觉。全局给每个 `button` 挂一个居中的透明伪元素，尺寸取「元素本身」和 `--hit`（24px，WCAG 2.2 的下限）里的大者：本来就够大的控件它就是 100%×100%，毫无影响；小控件才向外撑开。它绝对定位，不占布局，**密度一个像素都没变**。

两条例外要自己处理：

- **拥挤的清单自己把行高提到 `--hit`**（版本筛选那种一屏几百条的）。纯靠伪元素向外够，相邻两项的判定区会互相重叠——**点错比点不中更糟**。
- **不是按钮的东西不要变成按钮**。窗口边缘那几条 4px 的缩放把手是 `div`，全局规则碰不到它们；真把它们撑到 24px，贴边的内容就再也点不到了。

### 布尔开关不能只靠透明度

第三级那套「选中实色、其余淡出」的状态语言只说得清「N 选 1」。一个布尔开关（「含快照」）光靠深浅，用户根本看不出它可以点——它看起来就是旁边那个小标题的同类。所以它要一个方框：12px 的圆角小方块，勾上填强调色。这是这一层里唯一允许出现的边框，因为它承担的是「这里可以点」这个信息，不是装饰。

## 十二、耗时任务与岛

### 什么是作业

三条判据，缺一不可：

1. **生命周期比发起它的界面长**——走开再回来还得看得见
2. **有中间状态可说**——不只是转圈，而是「到哪一步了」
3. **失败需要被接住**——不能随组件一起消失

进：补全实例、启动、装资源、装整合包。不进：搜索、读详情、扫 Java、复制实例——那些是 `async` 加一个局部加载状态就够了的事，它们要的是**取消**，不是记账。登录是**对话**（等的是人），游戏在跑是**状态**（没有进度也不会完成），两者都不是作业。

### 进度分两轴，不压成一个百分比

纵轴是「第几步 / 共几步」，横轴才是这一步内部的字节数。

理由不是好看：一次补全里，装 Forge 那一步要在本地跑第三方安装器，它拆开 client jar 重打，根本**没有百分比可言**。混进「检查游戏文件」的代价是进度条撒谎——显示着下载，实际一动不动卡一分钟。分步之后它诚实地说「这一步不知道要多久」，整体靠步号表达。

总步数由每一段各报各的（`Job::expect` 是累加的）：启动那条路上启动报 1、补全报 4，合起来 5 步，谁都不必知道别人有几步。后端还没说总数时 `of` 是 0，界面就不显示分母——**不编一个假的**。

### 岛：顶栏右段那块会变形的状态区

借灵动岛的**交互语法**，不是它的样子。iPhone 上那块黑药丸成立是因为那个位置本来就有挖孔；Fern 没有挖孔，凭空浮一个纯黑胶囊只会像贴在封面上的创可贴。

值得借的四条：紧凑形态常驻、交互时连续变形而非弹出新窗口、多状态时分裂成主胶囊加卫星、**零状态时彻底消失**（移出 DOM，不是 opacity 0）。最后一条和「出厂零挂件」同构。

位置：右缘钉死（顶着设置与头像），向左长。中段是五个场景词的圣地，岛不去。

**岛只读，不存。** 这一层一份状态都不新增，它是一个投影：把散落各处的现有状态映成同一个 `Presence`，排个序。没有注册／注销的生命周期，也就没有「作业结束了但岛没收到」这类第二真相来源的 bug——因为根本没有第二份真相。各特性在自己的模块里调一次 `contributes()`；**加一种新状态，顶栏和岛的组件一个字不用改**。

优先级：`失败 > 游戏运行 > 联机房间 > 作业进行中`。失败排最前尽管它既不最新也不最热闹——前三种都是在发生的事，看不看都不影响你；失败是唯一需要你做点什么的。**成功的作业直接消失**（新实例出现在曲库里本身就是最好的完成通知），**失败的留到有人点掉**。

一条判据管住表演欲：**岛只承载进行时。** 说不出「正在……」的东西不进——保存成功、复制了邀请码、有新版本可用，那些是 toast、是局部状态、是设置页里的一行字。

游戏运行中的形态多带一样东西：胶囊底边一条随堆水位变化的细线（`Presence.fill`）。它和进度是两个字段，不能合并——进度会走到头、会「完成」，所以紧凑那一行会把它读成百分比；水位一直在动，永远不会完成。数据来自启动时注入的 GC 日志，和自适应内存分配读的是同一条流，所以这条线是免费的。**读不到就不画**：一条编出来的线比没有线更糟。

### 通知：说完就走的那一句

`components/Notices.svelte` + `lib/notices.svelte.ts`，右下角。承载上面那条判据划出去的东西：**一件已经发生完的事**——已安装、已保存。三条纪律：只说结论不说过程（有进度的是作业，归岛）；自己消失（需要人处理的是错误，归岛的 alert 形态，它会留到有人点掉）；最多带一个动作（两个以上的选择说明这件事还没做完）。

它挂在外壳上，不挂在任何场景里。上一版没有这一层，于是每一屏各自造一个「成功了」的块——项目详情页在版本列表上方长出一段「已安装 5 个文件」。那种块的问题是**位置绑死在触发它的控件旁边**：导航一走就没了（而那件事其实已经完成），留在原地又会把布局顶开一块。

### 两条踩过的坑

- **同步命令会冻住整个窗口。** Tauri 里不带 `async` 的命令在主线程上跑，那正是 webview 事件循环所在。碰磁盘、碰钥匙串、起进程的一律扔进阻塞线程池；只算路径的留在原地。
- **变形时唯一允许动的是不占位的东西。** 胶囊留在 flex 流里为自己占位，展开的面板绝对定位。面板高度用 `grid-template-rows: 0fr → 1fr`——那是唯一能真正动起来的「到内容高度」的过渡，比写死 `max-height` 诚实。

## 十三、设置：什么该进这一页

设置页会变成杂物间，不是因为有人偷懒，是因为没有判据——每一项单看都「好像该有个开关」。所以先立排除线：

| 这一项属于 | 它该在 |
|---|---|
| 某一个实例 | 实例设置 |
| 某一次操作 | 就地解决（岛、对话框、那一屏自己） |
| 某个身份 | 账户那一节的名单，不是一个全局开关 |
| 剩下的：跨实例、跨会话 | 设置页 |

分区不按「功能模块」切，按**你会为了什么来这一页**切：外观 / 账户 / 游戏 / Java / 下载 / 数据 / 关于。

### 设置有两级：一行可以是一个入口

根页是那张表单：七节，每节若干行，改一行就是改一个值。**但有些东西不是一个值。** 一个账户有名字、UUID、类型、皮肤站、绑定的实例，还有「设为当前 / 改名 / 移除」三个动作——把它塞进表单的一行，就只能塞成就地展开的东西：看一眼 UUID 要撑开那一行，添加账户要在名单中间撑开一整张表单，而撑开的那一刻，下面所有的行都往下跳一截。三种登录方式要问的字段还各不相同（离线一个名字、正版一个八位码、外置三个字段），撑开的高度每次都不一样。

所以第二级：`nav.focus` 的语法是 `分区/行/目标`，第三段存在时整块换成二级页。它和场景的纵深是同一套语法——就地展开、一次返回回到上一层、Esc 由外向内逐层退——只是发生在浮层内部。二级页不保留左侧那列锚点：那列回答的是「这一长页我要看哪一段」，而人已经不在那一页上了。

把位置放进 `nav.focus` 而不是设置组件自己的局部状态，是因为**能被 ⌘K 直接送达的地方，和用户此刻站着的地方，不该是两个变量**。二级页因此自动可寻址（搜「账户档案」直接落到某个账户），Esc 也就知道该先退哪一层。

### 「游戏」是起点，不是替代品

全局默认那一层的存在理由：没有它，每建一个实例都要把同样的选择再做一遍，而人只会做一次——之后的实例全都带着一份自己没选过的默认值。

实例设置回答「这一个要不要特别一点」，全局回答「一般情况下是什么样」。所以实例那边的选项是**三档**，不是两档：

```
跟随全局（G1）   我不管，以后全局改了它跟着变
G1               就要 G1
ZGC              就要 ZGC
```

把前两个合成一个，等于让一次沉默变成一次表态。

### 有自动算法的东西，全局设的是算法的参数，不是结果

内存不能做成「默认多少 MB」——那会和实例里的「自动」正面打架：两个都在说「我不管你决定」，答案却不一样。

正确的做法是找出那个算法里**唯一一个只有用户知道答案的量**，把它拿出来。内存分配的自由参数有四个（上限比例、基线比例、整合包档位、地板），其中只有一个是用户的知识而不是我们的：**这台机器上还跑着什么，所以最多能把多少内存交给游戏。** 其余三个是我们的判断，摆出来只会变成一排没人敢动的开关。

而这个量本来就在代码里，硬编码成「物理内存的一半」。**把它拿出来当设置不是新增一个概念，是给一个已经在承重的常数起个名字。**

一个数字一个意思：它同时夹住自动算出来的堆和实例里手填的值。想给某个实例更多，那就是在决定多分一点机器给游戏，该抬的是这条线——不该有一条能绕过它的旁路，否则这条线就不是线。

没有自动算法的东西（GC、窗口尺寸、额外 JVM 参数）就老实一点：全局一个值，实例可覆盖。

## 十四、命令面板：一套带文本界面的寻址系统

图形界面的契约是「能做的事都看得见，靠看来发现」。它在两个方向上会破：**距离**（东西看得见，但在四次点击之外，成本在走而不在找）与**数量**（三百个实例、五千个模组，再好的排版也无法让目标可见）。面板用命名替代导航，同时解决这两个。

所以面板不是「一串命令加模糊搜索」，而是一套寻址系统——而导航层本来就是一套寻址系统。文档里那句「⌘K 是这套路由的键盘化身，一处定义两处使用」要兑现，靠的是让路由表本身成为面板的一个来源：场景、设置的每一节都自动可搜，加一节不必另行注册。

### 名词 × 动词

人往里打的只有三类东西：名词（去到某个东西）、动词（做一件事）、动词加名词（一次事务）。多数面板只做前两类，第三类靠「动词隐式作用于当前选中项」蒙混过去——VS Code 可以这样，因为它有一个极强的环境选中项：当前打开的文件。

Fern 没有。对象是异质的（实例、账户、位置、模组），而「当前实例」这个上下文很弱。所以两个方向都必须成立：

```
名词优先   [对象] → 对它能做什么
动词优先   [动词] → 对谁做
```

落到实现上只有一条规则：**对象有类型，动作声明它接受什么类型的对象。** 动作有默认宾语就一步到位，没有就下钻去问。这一条替掉了此前散落在外壳里的全部特判。

### 四条约束

- **注册写在暴露这个动作的模块里**，不集中成一张表。外壳曾经手写一张动作表，于是它被迫认识启动、日志、目录、设置——加一个功能就要回来改它一次。这也是那条纪律唯一守得住的方式：面板里出现的每个动作，界面上都有一个看得见的入口。面板是加速器，不是功能的藏身处。
- **下钻与预过滤共用一个机制。** 输入框左侧的 chip 既是「校验哪个实例」的追问，也是切换器进来时锁定的类型。不写两套。
- **面板不显示进度。** 从面板发起校验之后面板关闭，岛接手。面板发起，岛报告。
- **面板只做选择，不做输入。** 「新建实例」需要名字和版本，那不该在面板里长出一个表单，它跳到真正的界面去。这一条是防止面板变成第二个应用的闸门。

### 排序

按分数排，组标题只是类型变化处的分隔线。固定组序好记，但当最佳答案在第三组时它就是错的；可预测性由「同一个查询永远同一个顺序」保证。真正需要位置稳定的是刚打开还没输入的那一刻。

匹配用带质量分的子序列：连续命中与词首命中加权，所以「fabopt」在「Fabulously Optimized」上的得分远高于在一段碰巧含有这些字母的描述上。频次与时间加权（半衰期十四天）叠在分数上——人要的东西分布极度偏斜且与时间相关，不学习的面板等于要求用户永远输入同样的字符。

不是所有对象都平铺在顶层。账户只在下钻里出现：一份五个账户的名单会把实例和动作挤下去，而打开面板十有八九是要换实例。

### 联网结果只向下追加

「面板不联网」这条界限画错了：模组在这个应用里就是一等对象，没有理由排除。真正的约束是——

> **面板永远不能让你为「你已经知道自己要什么」的那件事等待。**

这是可满足的，靠两条：本地结果立即渲染；远端结果**只向下追加，永不重排已经画出来的部分**。慢结果因此不会把你正要按回车的那一行挪走。保证写在面板这一层，不交给每个来源自觉——它一旦被破坏，就是最难察觉的那种坏。

查询变了就作废尚未返回的答案。请求本身取消不了（Tauri 的 invoke 没有取消口子），但不采信是必须做到的：一个已经不对应当前输入的答案追加进来，比慢更糟。

面板与浏览页的分工由此确定：**面板是「我知道我要什么」，补给是「我不知道我要什么」。** 所以面板只做直达，不复制筛选、排序、分页——那些是「不知道要什么」时才需要的东西。搜不到想要的，最后一行把已经打过的字交接给补给站。
